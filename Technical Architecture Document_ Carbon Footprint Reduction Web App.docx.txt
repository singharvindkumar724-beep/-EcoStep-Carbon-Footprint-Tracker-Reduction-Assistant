Technical Architecture Document: Carbon Footprint Reduction Web App
Role perspective: Senior SaaS Architect
1. Executive Summary
This document proposes a production-ready architecture for a carbon footprint tracking platform that helps users understand, track, and reduce their emissions through personalized recommendations, habit tracking, and AI-driven insights.
Goals
Simple onboardingA non-expert user can estimate their footprint in under 5 minutes.
Actionable insightsThe system converts data into specific, measurable recommendations.
Long-term engagementUsers can track habits, progress, goals, and achievements over time.
Scalable architectureDesigned for SaaS growth with clear separation of concerns.
Antigravity / AI Evaluator Fit
This design emphasizes maintainable code, practical AI usage, secure defaults, efficient resource use, accessibility, and optional Google Cloud integrations (Firebase, BigQuery, Gemini AI, Cloud Run) that align with the evaluation criteria.

3. High-Level Architecture
System Components
Web Client (Next.js)Dashboard, onboarding, tracking, goals, insights, reports.
API LayerAuthentication, CRUD operations, calculations, AI orchestration.
Database (PostgreSQL)Stores users, activities, emissions, goals, recommendations, and audit data.
AI ServiceGenerates personalized reduction advice based on user patterns.
Analytics & MonitoringUsage tracking, error reporting, performance monitoring.
Data Flow
Example: User logs a car trip.
User submits trip distance.
API validates input.
Emission factor is retrieved (car, fuel type, etc.).
CO₂e is calculated and stored.
User dashboard aggregates totals.
AI engine updates recommendations (e.g., “replace one weekly car trip with public transport”).

6. Core Business Logic
Emission Calculation
Formula:
CO₂e = Quantity × Emission Factor
Example:
Activity
Car travel
Distance
50 km
Emission factor
0.192 kg CO₂e/km
Result
9.6 kg CO₂e
Recommendation Engine
Start with a rule-based engine, then optionally augment with AI.
Rule examples
High transport emissionsIf transport > 40% of total footprint → suggest public transit, carpooling, biking, or EV transition.
High food emissionsIf food emissions are high and diet is omnivore → suggest reducing high-impact foods.
High energy emissionsIf energy emissions are high → suggest LED lighting, appliance efficiency, and renewable energy options.

Final Recommendation
For the Antigravity evaluation, I would build this as a TypeScript-based Next.js + PostgreSQL + Prisma application, use Auth.js for authentication, and integrate Gemini API for personalized recommendations. This combination provides strong code quality, maintainability, security, and Google ecosystem integration while remaining simple enough to implement within a hackathon-style timeframe.
