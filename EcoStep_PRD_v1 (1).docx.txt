1. Executive Summary
EcoStep is a web-based, AI-powered carbon footprint tracker that helps individuals understand, monitor, and reduce their personal environmental impact through guided daily actions and hyper-personalized insights. Unlike generic carbon calculators that give users a number and leave them stranded, EcoStep creates a continuous feedback loop — connecting daily habits to climate impact and translating that impact into concrete, achievable next steps.

The product is designed to be the intelligent climate companion that general consumers never had: approachable, motivating, and genuinely useful — not guilt-inducing or overwhelming.

2. Problem Statement
2.1  The Core Problem
Climate anxiety is rising, but individual action remains paralysed. Most people know they should reduce their carbon footprint, but three friction points stop them cold:
Lack of visibility — they cannot see how their daily choices (diet, transport, shopping) actually translate into CO₂ emissions.
Overwhelm — when they do look it up, the data is complex, guilt-laden, and disconnected from their personal context.
No personalised guidance — generic tips like 'drive less' or 'eat less meat' are not actionable without context of what would actually move the needle for that individual.

2.2  Why Now
Global search interest in 'carbon footprint calculator' has grown 3× in 5 years.
Younger demographics (18–35) report high climate concern but low confidence in their ability to act.
AI now makes truly personalised, conversational guidance economically viable at scale.
This challenge vertical directly aligns with the hackathon brief: smart, dynamic assistant with logical decision-making based on user context.

5. User Flow — End to End
5.1  First-Time User Journey

LANDING PAGE — User arrives via link/search. Clear headline ('Know your carbon footprint in 5 minutes'). Single CTA: 'Get My Score'. No login required to start.
ONBOARDING QUIZ (Steps 1–5) — AI-guided conversational quiz: (1) Location & household size, (2) Transport habits, (3) Diet & food preferences, (4) Home energy & heating type, (5) Shopping & flying frequency. Progress bar shown. Each question has smart defaults to reduce drop-off.
RESULTS REVEAL — Animated score reveal: 'Your estimated annual footprint is X kg CO₂e.' Contextualised: 'This is Y% above/below the Indian average of Z kg.' Breakdown donut chart by category. Strong hook before asking for sign-up.
SOFT SIGN-UP GATE — 'Save your score and get your personalised action plan.' Email + password or Google OAuth. Minimal friction — email optional; users can proceed as guest with localStorage persistence.
DASHBOARD (Home) — Personalised dashboard loads. Shows: score, top 3 AI-recommended actions, streak tracker, quick-log shortcuts.
FIRST AI INSIGHT — Proactive: 'Based on your profile, switching to a plant-based diet 3 days/week would save ~450 kg CO₂e/year — here is how to start.' Contextual, not generic.

5.2  Returning User Journey
LOGIN — One-click Google OAuth or remembered session.
QUICK LOG — 'What did you do today?' — User taps activity type (drove to work, had a steak, ordered online). AI auto-fills estimated CO₂; user confirms. 30-second task.
UPDATED DASHBOARD — Score updates in real-time. Trend line shifts. New insight unlocked if behaviour pattern detected.
ACTION TAKEN — User marks an action as 'Started' or 'Completed'. Footprint projection updates to show future impact of sustained habit.
WEEKLY REVIEW — AI-generated weekly digest: what changed, what improved, one focus for next week.

6. Minimum Viable Product (MVP) Definition
6.1  MVP Scope
The MVP is the smallest version of EcoStep that delivers genuine value to a first-time user and demonstrates the core AI intelligence loop to evaluators. It must be completable in a hackathon sprint, deployable from a single GitHub repository, and impressive enough to score high on code quality, accessibility, and AI logic.

6.2  MVP Feature Set
MVP Module
What Gets Built
Onboarding Quiz
5-step conversational form with carbon calculation logic. Score computed client-side using IPCC-referenced emission factors.
Carbon Score Engine
JavaScript/Python calculation module. Emission factors per activity category. Outputs kg CO₂e/year per category and total.
AI Insight Engine
Claude API (claude-sonnet-4) integration. Prompt receives user profile JSON; returns top 3 personalised actions ranked by CO₂ impact. Structured JSON response parsed into UI cards.
Dashboard UI
Responsive React/HTML dashboard. Donut chart (recharts or Chart.js) for category breakdown. Line chart for trend over time. Clean, accessible design.
Activity Logger
Form with dropdowns for activity type. Preset emission factors auto-fill CO₂ value. User confirms and saves to local state or simple backend.
Action Library
Static JSON of 50 actions with metadata (category, CO₂ savings, difficulty, cost). Filterable list with user personalisation score overlay.
Progress & Streaks
Session-persisted log history. Cumulative savings counter. Simple streak badge logic (3-day, 7-day, 30-day).
Authentication (optional)
Optional Google OAuth or email. App functions without it (localStorage fallback) to remove sign-up friction for demo.

6.3  Tech Stack Recommendation
Frontend: React (Vite) + Tailwind CSS — fast, modern, evaluator-friendly
AI: Anthropic Claude API (claude-sonnet-4-20250514) for insight generation
Charts: Recharts or Chart.js — lightweight, accessible
Storage: localStorage for MVP; Firebase Firestore for optional persistence
Hosting: Vercel or Netlify (free tier, single-command deploy from GitHub)
Emission data: Custom JSON based on IPCC AR6 emission factors (publicly available)

8. What We Are Deliberately NOT Building in V1
Scope discipline is a competitive advantage. The following are explicitly excluded from v1 to protect delivery quality and focus:

8.1  Excluded Features & Rationale
NOT Building
Why Not (and When to Build It)
Native iOS / Android apps
PWA delivers 90% of value at 10% of cost. App store approval adds delay with no hackathon benefit. Build native in v2 if user demand warrants.
Carbon offset marketplace
Requires vetted vendor partnerships, payment processing, legal review, and trust-building. High-risk for MVP. Introduce in v2 when user base exists.
Corporate / team accounts
Entirely different data model, permissions layer, and reporting needs. B2B requires a separate go-to-market. Not the target persona.
Verified / certified accuracy
True certified methodologies (GHG Protocol, PAS 2050) require domain-expert review and legal disclaimers. MVP uses best-effort IPCC factors with clear 'estimate' labelling.
Receipt and bill scanning (OCR)
Computer vision pipeline adds architectural complexity, cost, and latency. Nice-to-have for v1.1; not worth the risk in sprint 1.
Real-time integrations (bank APIs, smart meters)
OAuth flows with financial institutions require compliance reviews and lengthy API approval processes. Not feasible in hackathon timeline.
Social network / community feed
Community features require moderation infrastructure. Adds complexity without improving core value. Introduce social sharing (lightweight) in v1.1.
Gamification leaderboards
Public competitive leaderboards require anti-gaming logic and moderation. Simple personal streaks and badges are sufficient for v1 motivation.
Multi-language support
English-first for v1. Internationalisation (i18n) architecture should be designed in but strings not translated until user geography data warrants investment.

9. AI Design Notes — Scoring Alignment
Given the hackathon evaluates 'Ability to build a smart, dynamic assistant' and 'Logical decision making based on user context', the AI layer is the technical centrepiece. Below is the intended prompt architecture:

9.1  Insight Engine Prompt Design
The system prompt to Claude should instruct it to act as a climate coach. The user message should be a structured JSON object containing:
User profile: location, household size, diet type, primary transport, home energy type
Activity log: last 7 days of logged activities with CO₂ values
Current footprint: total and per-category breakdown
Actions already started or completed

The AI response should return a JSON object with: (1) top 3 personalised action recommendations, each with title, estimated CO₂ saving, personalisation rationale, and step-by-step guidance; (2) one encouraging contextual observation about their progress; (3) one concrete focus for the coming week.

9.2  Why This Scores High on Evaluation Criteria
Smart AI: Personalised output derived from structured user context — not static tips
Logical decision-making: Actions ranked by CO₂ impact × feasibility for that user's profile
Real-world usability: Insights are actionable, specific, and presented conversationally
Security: API key stored server-side or in env; never exposed in client bundle
Code quality: AI integration isolated in a dedicated service module, testable independently

Appendix — README Template for GitHub Submission
Include the following structure in your repository README.md to satisfy the submission requirement:

Vertical
Carbon Footprint Tracker & Reduction Assistant

Approach and Logic
EcoStep uses a structured AI pipeline: user lifestyle data collected via onboarding quiz is serialised into a JSON profile and sent to the Claude API (claude-sonnet-4) with a role-specific system prompt. The model returns ranked, personalised emission-reduction actions. Emission calculations use IPCC AR6 emission factors. All AI logic is isolated in /src/services/insightEngine.js for testability.

How the Solution Works
User completes 5-step onboarding quiz. Carbon score calculated client-side.
Dashboard loads with personalised AI insights fetched from /api/insights.
User logs daily activities. Score updates in real time.
AI engine re-evaluates profile weekly and refreshes recommended actions.
Progress tracked via streak system and cumulative CO₂ savings counter.

Assumptions Made
Emission factors are estimates based on IPCC AR6 global averages, not region-specific certified values.
User self-reported data is taken at face value; no validation of claimed behaviour.
MVP uses localStorage for persistence; production would require authenticated backend storage.
